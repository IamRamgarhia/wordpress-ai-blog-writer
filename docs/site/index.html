Installing #

Blogcraft needs WordPress 6.0 or newer and PHP 7.4 or newer. It is tested against WordPress 7.1 and every PHP version from 7.4 to 8.5.

  1. Download the zip

    Take the latest blogcraft-x.y.z.zip from the releases page.

  2. Upload it through WordPress

    Go to Plugins → Add Plugin → Upload Plugin, choose the zip, install, activate.

  3. Finish the setup

    The plugin opens a short setup screen. Three questions, all skippable, all changeable later.

Upload the zip rather than extracting it by hand. WordPress reads the folder name from inside the archive, so uploading replaces a previous version cleanly. Extracting with a file manager creates a folder named after the zip with the real plugin inside it — and two copies of the same plugin is a fatal error on activation. Blogcraft detects this and stands aside with a notice naming the folder to delete, but it is easier not to get there.

Connecting a provider #

Blogcraft has no AI of its own. It uses an account you own, with a key you paste in, and every request is billed to you by that provider at their own rates. Nothing passes through anybody else, which is why there is no subscription and no credit balance.

Go to Blogcraft → Settings → Connect a provider. Choose the provider, paste the key, press Save settings. The model list is then read from your own account, so you pick from what your key can actually use rather than typing a model id from memory — which is the commonest way to end up with a setup that looks finished and fails on the first post.

Free AI models: what to use if you have no AI account at all

The provider list is grouped by what it costs, free first, because spending nothing is a supported way to use this plugin rather than a trial of it. Nothing is held back on a free provider — there is no paid tier here to unlock, and no feature that switches off.

Group one: free local AI models, no key, no account

These download a model once and run it on your own computer. Nothing leaves the machine, there is no bill and there is no signup. Install one, start it, choose it in Blogcraft and leave the API key blank — the address is already filled in for you.

Ollama no key

The simplest one to start with. One command downloads a model and it runs as a service in the background.

LM Studio no key

The same idea with a desktop app in front of it: browse models, click to download, switch the local server on.

Jan no key

Open source, offline by default, with a chat window of its own so you can try a model before pointing a blog at it.

llama.cpp no key

The engine underneath most of the others. Run llama-server yourself when you want the control.

Which local model? Blogcraft does not bundle or recommend one, because the answer depends on the machine. As a rule of thumb, an instruction-tuned model of around seven or eight billion parameters writes a readable post on an ordinary laptop; larger ones write better and need more memory. Write one short post first and read the scorecard — it will tell you plainly whether the model you picked can hold a structure, and swapping it is one field.

Group two: free tiers — a key, but no card

These are hosted, so they are faster than a laptop and need no local setup. Each gives away some usage at no cost. You create an account and a key; none of them asks for a card to get started.

Google Gemini free tier

A free tier large enough to write with, and the easiest hosted route for a first post. Sign up, create a key, paste it in.

Groq free tier

Also free to start, and notably fast — a twelve-step post finishes in a fraction of the usual time.

Mistral free tier

Open-weight models with a free tier, from the company that publishes them.

Hugging Face free tier

One token, hundreds of open models, and a free monthly allowance across all of them.

OpenRouter free models

One key for many providers, including a set of models that are free to call — those are the ids ending in :free.

Cerebras free credits

Free credits to start with rather than an ongoing allowance, then paid.

Free allowances move on each provider's schedule, not this plugin's. The settings screen links to every provider's own pricing page rather than repeating a number here that would be wrong by the time you read it.

Everything it works with

OpenAI, Anthropic, Google Gemini, xAI, Groq, DeepSeek, Moonshot, Mistral, OpenRouter, Together, Fireworks, Cerebras, Hugging Face, Ollama, LM Studio, Jan, llama.cpp, any OpenAI-compatible endpoint, and the WordPress AI Client.

A cheaper model for the bulk of the work

Most of a post's words — and so most of its cost — are written in the section, questions and extras steps, which are carrying out a plan the outline already made. There is a second model field for those. The outline, the opening, the critique and the rewrite stay on your main model, because those are the steps where a weaker one is paid for in every paragraph afterwards.

Your key never leaves your database in readable form. It is encrypted at rest and never written to a log, an error message or the screen. Switching provider does not carry the old key over: a key saved for one service is not treated as a key for another.

Describing your voice #

This is the single biggest reason two blogs using the same model do not read the same. It is sent with every request, and without it the model writes for nobody in particular — which is what generic sounds like.

Under Settings → Describe your voice:

FieldWhat to put in it
What this blog is about One or two sentences on the subject and the angle. Not a category — a position. "Home coffee equipment, tested properly rather than unboxed."
Who you write for Who is reading and what they already know. "People buying their first proper machine, who know what espresso is but not what a pressure profile is."
Style rules One per line. No em dashes. Short paragraphs. Never open with a question.
Extra banned words One per line. A list of the usual AI tells is already blocked.
Never write about Competitors, off-limits claims, anything legally sensitive.
Your own experience Standing facts about you or the site that apply to every post.

Let it read your existing posts

If you already have posts published, there is a button that reads them and fills these fields in from how you actually write. It is usually a better starting point than describing yourself from scratch.

Writing a post #

Blogcraft → Write a post. Only one field is required.

Topic

A sentence works better than a keyword. "How to choose a standing desk for a small home office" gives the model a question to answer; "standing desks" gives it a category to fill.

Angle for this post

Anything true of this one post only. This is what stops every post reading the same. "Compare three price brackets and say which is worth it."

What you know that nobody else does

The most important field on the screen, and the one most people skip. Your own numbers, results, prices, or what happened when you tried it.

"We tested 9 desks over 4 months. The £220 bracket wobbled above 110cm; the £400 bracket did not. Our own returns rate on the cheapest was 3 in 9."

It is the heaviest check on the finished post and the only part of a page a model cannot produce. Everything here is used as fact and never invented beyond — the model is explicitly told not to round these numbers, extend them, or produce another figure of the same kind.

Stuck? The What should I write about this? button reads your topic and asks you four specific questions instead. It never answers them for you: invented facts are exactly what this field exists to avoid.

Before it writes

Pressing Write this post opens a panel listing what has never been decided — whether anybody has described the voice, whether the writing rules are still the shipped defaults, whether it has anything to read but its own memory — and then the ten parts a post can be built from, each switchable for this post alone.

Nothing blocks. Write it now sits underneath all of it, and there is a Stop asking me this box if you would rather not see it again.

Watching it work

You are taken to a live progress screen. The title and headings appear as they are decided, a clock counts the real elapsed time, and each of the twelve steps fills in as it completes. Leaving the page is safe: it picks up where it stopped, and the navigation carries a Being written tab while anything is in flight.

The writing rules #

Blogcraft → How it writes is the brief every post is written to. Anything shown in monospace on that screen is measured on the finished draft, not merely requested.

Start from a shape

Eight shapes are offered — a definitive guide, a numbered list with a verdict, step by step, this against that, a data study, an argued opinion, a quick explainer, a hands-on review. Choosing one fills in every control on the other tabs. A hands-on review and a definitive guide are not the same shape, and the defaults are reasonable rather than right.

Or match an article you admire

Paste an address and Blogcraft reads that page, measures how it is built — length, section count, sentence rhythm, how it opens and closes — and sets your controls to match. It copies the shape, never the words.

What you can set

Shape

Length, fewest and most sections, how it opens, how it ends, and which blocks to include.

Voice

Tone, point of view, reading level, spelling, literary devices, contractions, em dashes.

Search

Primary keyword and density band, required terms, internal and external link targets, title and description limits.

Sounding human

Sentence variety, banned phrases, whether experience and statistics are required, paragraph and sentence ceilings.

The brief panel shows exactly what the model is told. It updates as you change anything, so there is no gap between what you set and what is sent.

Research #

With research on, the model is handed current sources and writes from them, and the finished draft is checked against those same sources for whether it says anything they do not. With everything off it writes from memory, which dates badly and can cite nothing.

Nothing is contacted until you switch it on. Every source is off by default. That is deliberate: a plugin that starts making outbound requests the moment it is activated has decided something on your behalf that was yours to decide.

Pictures #

Optional, and off until you ask. The article decides what a picture should show — the model that wrote the piece describes the scene — and the Pictures controls decide how it looks. That is the difference between a useful image and clip art of the headline.

A paid service is only ever used when you pick it, never as a fallback, so an image is never billed to you by accident. If you already write with OpenAI, Google or xAI, choosing the same one here uses the key you have already entered.

Pictures are fetched one per step rather than all at once, so a slow image service cannot hold up a post that is otherwise finished — and if one fails, the post is published without it rather than failing.

Alt text describes the picture rather than repeating the heading above it, because a screen reader announcing the same sentence twice tells the listener nothing about the image.

Looking for an alternative? #

Most AI writing plugins for WordPress work one of two ways. Either you buy credits and the vendor calls the AI on your behalf, or you pay a monthly subscription for the same thing with a different label. Both mean your content passes through somebody else's service, and both mean the price you pay is the model's price plus a margin.

Blogcraft is the third way: you bring your own API key. The plugin is free and open source, the AI account is yours, and the bill comes from the provider at their own rates with nothing added.

What people are usually searching for

If you arrived here after looking for a free AI writer for WordPress, an AI content generator with no monthly subscription, a WordPress plugin that uses my own OpenAI or Gemini API key, an open source alternative to credit-based AI writing tools, an autoblogging plugin that is actually free, or a way to run AI blog writing on a local model with no key at all — that is what this is.

Reading the score

Failures are shown first and expanded; passes are folded away. A flat list of twenty-five rows buries the four that need a decision among the twenty-one that do not.

Having another go

The review screen offers one more writing pass aimed at the faults it just listed. Worth knowing: the pipeline already runs critique and revise before you see anything, so this is a second attempt rather than a fix nobody tried. A rewrite is not deterministic and the measurements are, so a second attempt at four numbered faults often lands.

Where nothing failing is something a rewrite owns, no request is made and you are not charged for one. Where some are, the screen names the ones rewriting will not touch instead of quietly skipping them. The new score is shown against the old — including when it goes down, which happens — and there is a button to put the earlier version back, which costs nothing because it was kept.

What would hold this back

A separate panel lists the things working against the post being found: whether it duplicates a post you already have, whether it says anything that is only yours, whether anything on your site points at it, and whether it is shorter than the question deserves.

None of this predicts a position. Whether a page ranks depends on who else wants the same query and what your site has earned, and no plugin can see either. Anything claiming otherwise is inventing a number.

Where posts go #

A finished post is an ordinary WordPress post. It is written as real Gutenberg blocks, so every paragraph and heading is editable normally rather than arriving as one unopenable lump. On a site using the Classic Editor it writes plain HTML instead — detected, not configured.

By default it is saved as a draft and appears under Posts. Anything scoring below your threshold is set to pending instead and listed under Needs review, which only appears when something is actually waiting.

Your SEO plugin

Blogcraft detects Yoast SEO, Rank Math, SEOPress and All In One SEO and fills their title and description fields. With none installed it writes the description and the sharing tags into the page itself.

It also writes BlogPosting and FAQPage structured data, and a breadcrumb trail for search engines — unless an SEO plugin is already handling that, in which case it stands back rather than producing two of everything.

Saying that AI was involved

Google asks that automation be disclosed: that it was used, how, and why that helped the reader. Blogcraft writes a line into the byline saying so, on by default, with wording you can replace or switch off entirely.

Written by AI

One screen lists everything the plugin has produced: what is being written now, what is finished and waiting on you, and what is on your site with the score each was judged by.

WordPress only runs scheduled work when somebody visits the site, so a quiet morning can push a post later than the hour you chose. That is WordPress rather than Blogcraft. Posts written by hand are driven from your browser instead, which is why they work on hosts where scheduled tasks are unreliable.

When something breaks #

Test the connection first

Settings → Check it works sends one very short request and reports exactly what came back. It costs a fraction of a penny and is the fastest way to tell a wrong key from a wrong model id from a provider that is simply down. Saving a key runs it automatically.

The Activity screen

Every job, every step, and why anything stopped. API keys are never recorded there. A job still moving links to its own progress screen.

The plugin will not activate

Usually two copies installed. Blogcraft detects this and stands aside with a notice naming the folder to delete. Look in wp-content/plugins/ for a second folder — often named after a zip file — and delete it.

A post is stuck on one step

Each step is one request and each has a time budget. If a provider stops answering, the screen says so rather than spinning. Check Activity for the last error. A rate limit is waited out rather than counted as a failure, so a quota that resets in an hour does not burn the job.

"You exceeded your current quota"

Your provider's limit, not the plugin's. The job pauses and resumes on its own once the window passes. The progress screen shows when.

Every post scores badly on Internal links

Not a writing problem. It means the site has nothing else on the subject to point at. It improves as you publish more, and the plugin says so rather than pretending a rewrite would fix it.

The posts read like every other AI blog

Almost always one of three things: nobody has described the voice, the writing rules are still the shipped defaults, or the evidence field is empty. The panel that opens before writing tells you which.

Privacy #

  • Your key is encrypted in the database and never written to a log, an error message or the screen.
  • Nothing is contacted until you switch it on. Every research source and every picture service is off by default.
  • No telemetry, no phone-home, no analytics. The plugin never contacts us, because there is nothing to contact.
  • Your content goes to your provider and nowhere else. Topics, drafts and settings stay in your WordPress database.
  • IndexNow sends only the address of a published post, and only if you switch it on.

Deleting the plugin #

Deleting Blogcraft leaves your settings, your writing rules and its record of every post it wrote exactly where they are. Install it again and everything is as you left it.

That is deliberate. WordPress asks whether you meant to delete the plugin; it has no way to ask whether you also meant to delete the rest, and dropping database tables cannot be undone. Deleting a plugin to reinstall it, to move hosts, or to clear a half-finished upload is an ordinary thing to do, and none of those mean the work should be thrown away.

There is a box in Settings → If you delete this plugin if you do want it all gone. Ticking it is the only confirmation there will be.

Your posts are never affected either way. They are ordinary WordPress posts from the moment they are created.

Questions #

Is it really free?

The plugin is, entirely, under GPLv2. There is no pro tier and nothing is locked. The AI is billed to you by whichever provider you choose, and several have free tiers large enough to write with.

Do I need a paid API key?

No. The provider list is grouped by cost with the free routes at the top. Ollama, LM Studio, Jan and llama.cpp each run a free AI model on your own machine and need no key or account at all. Google Gemini, Groq, Mistral and Hugging Face give away hosted usage for a key with no card attached, and OpenRouter lists models that are free to call. Every feature works the same on any of them.

Will my posts rank on Google?

Nobody can promise that, and this plugin does not. Whether a page ranks depends on who else wants the query and what your site has earned, neither of which is visible from the words on the page. What Blogcraft does is measure the things that are checkable and tell you plainly what is working against a post.

Which free AI model should I use?

If you want to spend nothing at all, run a local model: install Ollama or LM Studio, pull an instruction-tuned model of around seven or eight billion parameters, and leave the API key blank. If you would rather not run anything on your own machine, Google Gemini's free tier is the easiest hosted route and Groq's is the fastest. Blogcraft does not recommend a specific model, because the right one depends on your machine and on what the provider is offering this month — write one short post and read the scorecard, which tells you plainly whether the model can hold a structure. Swapping it is one field.

Can Blogcraft run entirely offline?

Yes. Choose a local runtime as the provider, leave every research source switched off, and use no picture service or a local one. Nothing then leaves the machine at any point in the twelve steps — not the topic, not the draft, not your own figures.

How much does a post cost to write?

It depends on your provider's rates and the length you asked for. The Write screen estimates the tokens before you spend them, and the estimates are deliberately generous. A monthly cap is available.

Can I edit a post before it is published?

Yes. Nothing becomes a post until you say so. The review screen shows the full draft in an editor, with the score and every check beside it.

Does it work with Yoast or Rank Math?

Yes, and with SEOPress and All In One SEO. It fills their title and description fields automatically. With none installed it writes the description and sharing tags itself.

Are the posts real Gutenberg blocks?

Yes. Every paragraph, heading, list and table is a proper block. On a Classic Editor site it writes plain HTML instead.

Can it write in languages other than English?

Yes. Write the topic and the voice description in the language you want, and set the spelling preference under the voice controls. The measurements count characters rather than bytes, so non-Latin scripts are handled properly.

Will it publish without me looking?

Only if you switch automatic writing on. Posts written by hand always stop and wait for you, and automatic ones are saved as drafts unless you say otherwise.

What happens if I switch providers?

The key fields clear, because a key saved for one service is not a key for another. Counting it would mean the setup says "ready" and the first post fails several steps in on authentication.
